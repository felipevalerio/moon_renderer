
## 1. Estrutura geral de uma janela Win32

Toda aplicação Win32 clássica segue o mesmo esqueleto:

1. Registrar uma **classe de janela** (`WNDCLASSEXA`) — descreve o "molde" da janela (ícone, cursor, cor de fundo, e principalmente a função que trata mensagens).
2. Criar a janela de fato a partir dessa classe (`CreateWindowExA`).
3. Mostrar a janela (`ShowWindow` + `UpdateWindow`).
4. Rodar o **loop de mensagens** (`GetMessageA` / `TranslateMessage` / `DispatchMessageA`).
5. Tratar as mensagens dentro da `WndProc`.

No código, isso tudo acontece dentro de `main()`.

---

## 2. `WndProc` — a função de callback da janela

```rust
extern "system" fn wnd_proc(hwnd: HWND, msg: u32, w_param: WPARAM, l_param: LPARAM) -> LRESULT
```

- `extern "system"`: obrigatório porque o Windows chama essa função usando a convenção de chamada `stdcall` (em x86) — sem isso o ABI não bate.
- É registrada em `wc.lpfnWndProc = Some(wnd_proc)` e o Windows a chama automaticamente toda vez que algo acontece com a janela (clique, redimensionar, pintar, fechar, etc).
- `msg` é o código da mensagem (`WM_PAINT`, `WM_CLOSE`, `WM_DESTROY`, ...). `w_param` e `l_param` carregam dados extras dependendo da mensagem.
- Mensagens não tratadas explicitamente **precisam** cair no `DefWindowProcA` (comportamento padrão do sistema) — senão a janela quebra (não minimiza, não fecha, etc).

### Mensagens tratadas aqui:

**`WM_PAINT`** — pedido do sistema para redesenhar a área da janela.
- `BeginPaint` / `EndPaint`: par obrigatório. `BeginPaint` retorna um `HDC` (device context — "onde" você desenha) e prepara a região a pintar; `EndPaint` libera esse contexto. Nunca usar `GetDC` para pintura de `WM_PAINT`, é sempre `BeginPaint`.
- `GetClientRect`: pega o tamanho da área útil da janela (sem bordas/título), usado aqui pra centralizar o retângulo.
- `CreateSolidBrush(COLORREF(...))`: cria um "pincel" sólido de uma cor. `COLORREF` é `0x00BBGGRR` (ordem **BGR**, não RGB!) — repare que `0x00FF0000` aqui é **azul puro**, não vermelho (o comentário no código diz "blue_brush", então está coerente, mas é um detalhe fácil de errar).
- `SelectObject(hdc, blue_brush)`: "seleciona" o pincel no contexto de dispositivo — a partir daí, tudo que for desenhado usa esse pincel. Retorna o pincel *anterior* (`old_brush`), que deve ser restaurado depois.
- `Rectangle(hdc, left, top, right, bottom)`: desenha o retângulo preenchido com o pincel selecionado.
- **Importante:** todo `HGDIOBJ` criado (`CreateSolidBrush`, `CreatePen`, etc.) precisa ser destruído com `DeleteObject`, senão vaza recurso do GDI (limite baixo por processo no Windows). Aqui isso é feito corretamente: seleciona o pincel antigo de volta e só depois deleta o novo.

**`WM_CLOSE`** — disparado quando o usuário clica no "X" da janela.
- `DestroyWindow(hwnd)`: destrói a janela (isso vai gerar a mensagem `WM_DESTROY` em seguida). Separar `WM_CLOSE` de `WM_DESTROY` permite, por exemplo, perguntar "deseja salvar?" antes de fechar.

**`WM_DESTROY`** — a janela já foi destruída.
- `PostQuitMessage(0)`: posta uma mensagem `WM_QUIT` na fila, que faz o loop principal (`GetMessageA`) retornar `false` e o programa terminar. Sem isso, o processo fica pendurado mesmo com a janela fechada.

## 3. `main()` — registro e criação da janela

### `GetModuleHandleA(None)`
Pega o "handle" (identificador) do módulo/executável atual. É passado como `hInstance` na hora de registrar a classe e criar a janela — o Windows usa isso para saber a qual programa a janela pertence.

### `WNDCLASSEXA` — descrição da classe de janela
Campos relevantes:
- `lpfnWndProc`: ponteiro pra `wnd_proc` (o callback visto acima).
- `hInstance`: handle do módulo.
- `hIcon` / `hIconSm`: ícones grande/pequeno (aqui usando o ícone padrão `IDI_APPLICATION`).
- `hCursor`: cursor do mouse sobre a janela (`IDC_ARROW` = seta padrão).
- `hbrBackground`: pincel usado para pintar o fundo da janela automaticamente (aqui um brush preto, criado à parte com `hb` — note que esse `hb` nunca é deletado, é um pequeno leak).
- `lpszClassName`: nome da classe, usado depois em `CreateWindowExA` pra dizer "quero uma janela desse tipo".
- Sufixo **`A`** nas structs/funções (`WNDCLASSEXA`, `CreateWindowExA`, `RegisterClassExA`...) = versão **ANSI** (strings `&str`/`char*` comuns). O Windows moderno prefere a versão **W** (`WNDCLASSEXW`, wide/UTF-16), mas ANSI ainda funciona.

### Strings para a WinAPI: `PCSTR`
```rust
let class_name = "myWindowClass\0";
let class_name_pcstr = PCSTR::from_raw(class_name.as_ptr());
```
- `PCSTR` = ponteiro C-style para string ANSI terminada em `\0`.
- **Cuidado**: o `\0` manual é essencial — WinAPI espera strings null-terminated, Rust `&str` normalmente não tem isso.
- **Ponto de atenção (bug em potencial)**: `class_name` e `window_name` são `let` locais dentro de `main`. Como `main` roda até o fim (loop de mensagens incluso) e essas variáveis não são movidas, elas continuam vivas durante todo o uso — então funciona aqui, mas é um padrão frágil. Se esses `PCSTR` fossem usados fora do escopo onde a `String`/`&str` original existe, seria um ponteiro pendurado (use-after-free).

### `RegisterClassExA(&wc)`
Registra a classe no sistema. Retorna `0` em caso de falha — por isso o `if RegisterClassExA(&wc) == 0` trata o erro com `MessageBoxA`.

### `CreateWindowExA(...)`
Cria a janela em si, parâmetros principais:
- estilo estendido (`WINDOW_EX_STYLE(0)` = nenhum),
- nome da classe e da janela,
- `WS_OVERLAPPEDWINDOW` = estilo padrão de janela "normal" (com borda, título, botões min/max/close),
- posição `CW_USEDEFAULT, CW_USEDEFAULT` = deixa o Windows escolher,
- tamanho `800x600`,
- pai/menu/instância/param extra = `None`.

Retorna `Result<HWND, Error>` — daí o `match hwnd { Ok(...) => ..., Err(...) => ... }`.

### `ShowWindow` + `UpdateWindow`
- `ShowWindow(hwnd, SW_SHOW)`: torna a janela visível (ela é criada invisível por padrão).
- `UpdateWindow(hwnd)`: força um `WM_PAINT` imediato, sem esperar o próximo ciclo do loop.

### O loop de mensagens
```rust
let mut msg = MSG::default();
while GetMessageA(&mut msg, None, 0, 0).as_bool() {
    let _ = TranslateMessage(&msg);
    DispatchMessageA(&msg);
}
```
- `GetMessageA`: bloqueia até chegar uma mensagem na fila da thread. Retorna `false` só quando recebe `WM_QUIT` (por isso o loop termina quando `PostQuitMessage` é chamado lá na `WM_DESTROY`).
- `TranslateMessage`: converte mensagens de teclado (`WM_KEYDOWN`) em mensagens de caractere (`WM_CHAR`) — necessário pra input de texto funcionar direito.
- `DispatchMessageA`: entrega a mensagem pra `WndProc` da janela correspondente (é essa chamada que efetivamente dispara `wnd_proc`).

## 4. Resumo mental do fluxo

```
main()
 ├─ GetModuleHandleA          → identifica o processo
 ├─ RegisterClassExA(wc)      → registra "modelo" de janela (com wnd_proc)
 ├─ CreateWindowExA           → cria a janela de fato
 ├─ ShowWindow / UpdateWindow → mostra e força primeiro paint
 └─ loop: GetMessageA → TranslateMessage → DispatchMessageA
                                                  │
                                                  ▼
                                        wnd_proc(hwnd, msg, ...)
                                          ├─ WM_PAINT   → desenha retângulo
                                          ├─ WM_CLOSE   → DestroyWindow
                                          ├─ WM_DESTROY → PostQuitMessage(0) → encerra o loop
                                          └─ outros     → DefWindowProcA
```

## 5. Pontos de atenção / possíveis melhorias

- `COLORREF` é **BGR**, não RGB — fácil de confundir cores.
- Todo objeto GDI criado com `CreateXxx` precisa de `DeleteObject` correspondente (o `hb` do fundo da janela não é liberado — leak pequeno, mas existe).
- Strings `PCSTR` dependem de o buffer original (`&str` com `\0`) continuar vivo enquanto o ponteiro for usado — funciona no código atual porque tudo está no mesmo escopo de `main`, mas é um padrão que quebra fácil se refatorado.
- Sufixo `A` = ANSI. Para suporte completo a Unicode, o caminho seria migrar pra `W` (`WNDCLASSEXW`, `CreateWindowExW`, etc.) usando `PCWSTR` com strings UTF-16.


Para passar um ponteiro (referencia) para o wnd_proc é necessário utilizar a função CreateWindowExA.
Nela existe uma parâmetro específico já reservado para caso seja necessário enviar algo (uma estrutura de dados, um ponteiro para um vetor etc...)
para a wnd_proc.

O parâmetro é o lpparam aceita um ponteiro para um valor a ser passado para a janela por meio da estrutura CREATETRUCT 
No caso de Rust este valor foi passado como Some(framebuffer as *const std::ffi::c_void) onde "c_void" é um tipo de dado 
usado para representar um ponteiro genérico do tipo C (void*).

Mas ele é diferente da palavra reservada "void" em C usada para retorno de funções.

SetWindowLongPtrA -> usado para salvar a estrutura (meu ponteiro/referencia) dentro da janela (wnd_proc) durante o WN_CREATE
GetWindowLongPtr -> usado para recuperar a estrutura que foi salva. Usado dentro do WN_PAINT
